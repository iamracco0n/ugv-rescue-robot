# 로봇 2대 동시 수색 — 설계

2026-08-10 · 단일 로봇 7/7 달성본(`701c6d8`) 위에서 시작한다.

## 목표

두 대가 한 건물을 나눠 수색해 전원 발견 시간을 줄인다.

**사전 고정 판단 기준**

- 조난자 **7/7 유지**
- 전원 발견 시간이 1대(2053~2256초)보다 **유의하게 단축**
- 2배는 기대하지 않는다. 중복 수색과 통로 간섭 때문에 **1.4~1.6배면 성공**

## 지금 구조의 걸림돌

전부 전역 네임스페이스다. `/scan`, `/cmd_vel`, `/camera`, `/tf`, `/map`
이름이 하나뿐이라 2대를 띄우면 서로를 덮어쓴다.

특히 **URDF 안의 gz 센서 토픽이 절대경로**다(13곳). `<topic>/camera</topic>`
처럼 박혀 있어 두 로봇이 같은 gz 토픽에 쓴다. 여기가 가장 먼저 터진다.

링크 7개(`base_footprint`, `base_link`, `laser_frame`, `camera_link`,
`turret_link`, `gun_link`, 바퀴)도 TF 이름이 겹친다.

## 설계

### 로봇별 / 공유 구분

**로봇별** (`/ugv1`, `/ugv2`): gz 모델·센서, 브리지, `robot_state_publisher`,
slam_toolbox, Nav2 한 벌, 비전 4노드

**공유(전역)**: 병합된 `/map`, 조난자 명부, 화재 구름, 관측 격자, 목표 선점

xacro 에 `prefix` 인자를 넣어 TF 프레임(`ugv1/base_footprint`)과 gz 센서
토픽(`/ugv1/scan`)을 로봇별로 만든다.

### 지도 공유 — 각자 SLAM + 병합

각 로봇이 자기 slam_toolbox 를 돌려 `/ugv1/map`, `/ugv2/map` 을 만들고,
병합 노드가 하나의 `/map` 으로 겹친다.

**정렬을 탐색할 필요가 없다.** 스폰 위치를 우리가 정하므로 두 map 프레임의
오프셋을 이미 안다. `map → ugvN/map` 정적 변환을 깔고 격자를 겹치면 된다.

TF 사슬:

```
map ──(정적, 스폰 오프셋)──> ugvN/map ──(slam_toolbox)──> ugvN/odom
                                          └──> ugvN/base_footprint
```

버린 대안: **한 대만 SLAM.** 다른 로봇이 간 구역이 지도에 안 생겨 거기로
경로를 못 낸다.

**위험**: 두 SLAM 이 각자 드리프트하면 병합 지도에 벽이 두 겹으로 보일 수
있다. 시뮬 odom 은 거의 정확해서 작을 것으로 보지만 **측정할 항목이다.**

### 표적·커버리지 공유 + 목표 선점

- **조난자 명부** — `target_manager` 는 자기 로봇의 포탑을 조준해야 하므로
  로봇별로 둔다. 확정된 조난자를 전역 토픽에 올리고 서로 구독해,
  **기존의 거리비례 중복 병합 로직을 그대로 재사용**해 합친다.
  `expected_victims` 판정이 합산 명부로 돈다.
- **관측 격자** — 각 `patrol_navigator` 가 자기 `_seen` 을 발행하고 상대 것을
  OR 한다. 한 로봇이 눈으로 훑은 방을 다른 로봇이 다시 안 간다.
  기존 `/coverage_map` 은 벽과 관측완료가 둘 다 -1 이라 모호하므로
  **전용 격자를 새로 낸다.**
- **목표 선점** — 각자 현재 목표를 발행하고, 상대 목표 반경 안의 후보는
  점수 계산에서 뺀다.

### 실행 머신

**OMEN 에서 돌린다**(Ryzen 9 7950X3D 32스레드, RTX 3090 Ti).
lab-main(5800X 16스레드, 3060)은 1대에 이미 load 8.7 이라 2대가 안 들어간다.
lab-main 은 개발과 1대 GUI 관찰용으로 쓴다.

## 단계

크기가 크므로 단계마다 확인하고 넘어간다.

| 단계 | 내용 | 확인 |
|---|---|---|
| 1 | 2대 스폰 + 네임스페이스 + 각자 SLAM/Nav2 | 두 대가 서로 안 밟고 각자 움직이는가 |
| 2 | 지도 병합 | 병합 지도에 벽이 두 겹 안 생기는가 |
| 3 | 표적·커버리지 공유 + 선점 | 같은 방을 두 번 안 가는가 |
| 4 | 채점 도구 2대 대응 + 큰 월드 검증 | 위의 판단 기준 |

## 위험

- **좁은 복도 교착.** 두 로봇이 서로 막을 수 있다. Nav2 가 상대를 라이다로
  보고 피하긴 하지만 돌려봐야 안다. 1단계에서 바로 드러난다.
- **병합 지도 이중벽.** 위 참조.
- **CPU.** OMEN 으로 옮겨 해결했다고 보지만 실측 전이다.
- **채점 도구가 1대 전제.** 4단계에서 다시 쓴다.

## 범위 밖

3대 이상은 이번에 안 한다. 2대가 되고 나서 판단한다.
