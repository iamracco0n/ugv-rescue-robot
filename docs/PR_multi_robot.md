# 로봇 2대 병렬 수색 + 검출 실패 원인 규명

단일 로봇 수색에 **두 번째 로봇**을 붙이고, 그 과정에서 드러난 **조난자
검출 실패의 진짜 원인**을 찾아 고쳤다.

커밋 54개. 크게 세 갈래다.

1. 2대 병렬 수색 (구역 분할 · 지도 병합 · 동료 돕기)
2. 검출 실패 원인 규명과 수정 (카메라 기하)
3. 측정 도구와 실험 설계

---

## 1. 2대 병렬 수색

### 넣은 것

| 항목 | 파일 |
|---|---|
| 로봇별 이름공간(TF·토픽·노드) | `ugv.urdf.xacro`, `sim_robot.launch.py` |
| 2대 동시 기동 | `multi_robot_sim.launch.py` |
| 지도 병합 | `map_merge_node.py` |
| 표적·화재 공유, 목표 선점 | `patrol_navigator.py`, `fire_detection_node.py` |
| 구역 분할 + 다 끝내면 동료 돕기 | `patrol_navigator.py` |
| 다중 로봇 RViz | `ugv_multi.rviz`, `tf_relay_node.py` |

### 잰 것

**1200초 시점 발견 인원**으로 1대와 2대를 짝지어 비교했다. 같은 머신·같은
시간대에 이어서 돌려 머신 성능차가 안 섞이게 했다.

| 머신 | 2대 | 1대 |
|---|---|---|
| OMEN r1 | 7명 | 3명 |
| OMEN r2 | 6명 | 5명 |
| OMEN r3 | 6명 | 4명 |
| 메인 | 7명 | 6명 |

**4쌍 전부 2대 승, 평균 +2.0명(4.5 → 6.5).** 약 1.4배다. 두 머신에서
재현됐다.

작은 월드에서는 이득이 없었다. 2대가 값어치를 하려면 방이 충분히 많아야
한다.

> 이 수치는 조난자 자세를 바꾸기 전 월드에서 잰 것이다. 지금 월드는 누운
> 사람이 늘어 더 어렵다.

### 지표를 두 번 바꿨다

처음에는 '전원 발견까지 걸린 시간' 으로 쟀는데 못 쓸 지표였다. 7명 중 가장
늦게 찾은 한 명이 값을 정하는 최댓값 통계라 편차가 크고(같은 조건에서
700초와 2672초), 시간 안에 못 끝낸 런은 숫자가 아예 안 나와 표본에서
빠진다. 완주한 런만 비교하게 되어 편향이 생긴다.

고정 시간에 센 인원수는 둘 다 피한다. 모든 런이 값을 내고, 최댓값이 아니라
누적량이라 편차가 작다. (`tools/victims_at.py`)

## 2. 검출 실패 원인 규명

### 무엇이 문제였나

2대를 붙이고 나서도 **7/7 완주가 절반**에 그쳤다. 조난자별로 갈라 보니
원인이 하나로 좁혀졌다.

| 조난자 | 자세 | 발견률(46런) |
|---|---|---|
| 침대 환자 | 침대에 누움 | **41%** |
| 바닥 누움 | 누움 | **70%** |
| 나머지 다섯 | 서있음·앉음 | 89~100% |

의도적으로 잔해에 가려 놓은 조난자는 **100%** 였다. 어려운 배치는 잘 찾고
**누운 자세**를 못 찾았다.

### 손잡이를 다섯 개 돌렸는데 하나도 안 움직였다

`dirs`(관측 방향 기록), `ghost`(유령 자리 기억), `room_bonus`(방 우선),
누운 사람 관문 완화, `det_conf`(박스 신뢰도). 전부 재고 되돌렸다. 근거는
각 커밋에 남겼다.

특히 관문 완화가 왜 안 통했는지가 실마리였다. 검출은 두 단계인데,

```
1단계  YOLO 가 사람 박스를 만든다     <- det_conf
2단계  박스의 관절점을 검사한다        <- 관문
```

누운 조난자를 놓친 런에서 **'후보로 잡았는데 관문에서 떨어짐' 이 0건**이고
거의 전부 **'후보로 잡은 적도 없음'** 이었다. 2단계에 도달한 적이 없으니
2단계를 아무리 풀어도 아무 일이 안 일어난다.

### 사진을 봤더니 바로 나왔다

숫자를 그만 돌리고 로봇을 누운 조난자 2m 앞에 세워 카메라 화면을 저장했다.

**몸이 화면 아래로 잘려 있었다.** 신발과 다리만 들어오고 몸통·머리는
프레임 밖이었다. 검출 박스는 안 그려졌다.

계산과 맞는다. 카메라 높이 0.5m, 수직 FOV 48.9도 — 수평으로 조준하면
**화면 아래끝이 바닥과 만나는 지점이 1.10m** 다. 그보다 가까운 바닥은
아예 안 찍힌다. 실측 검출 성공 거리도 누움 2.3~4.9m(2.3m 보다 가까운
성공 0건) 대 서있음 3.5~5.5m 였다.

### 고친 것 — 탐색 중 포탑을 아래로

`search_pitch` 기본값 0 → 0.10rad(5.7도). 화면 아래끝이 1.10m → 0.86m 로
당겨진다.

먼저 0.20 을 수평과 비교해 채택했다(2머신 18런).

| | 0.20 | 0 (수평) |
|---|---|---|
| 누운 3명 발견률 | 21/27 (78%) | 14/27 (52%) |
| 7/7 완주 | 6/9 (67%) | 2/9 (22%) |
| 누움 최소 검출거리 | 1.3m | 2.0m |

그런데 0.20 이 최적인지는 안 재봤다 — 처음 고른 값이 그냥 통한 것이다.
0.10 / 0.20 / 0.30 을 훑으니(18런, 값당 6런) **0.10 이 더 나았다.**

| 각도 | 누움 | 서있음 | 7/7 |
|---|---|---|---|
| **0.10** | **18/18** | **18/18** | **6/6** |
| 0.20 | 16/18 | 16/18 | 4/6 |
| 0.30 | 15/18 | 17/18 | 4/6 |

0.30 은 위쪽 시야가 7.3도까지 줄어 오히려 나빠진다. 0.10 이면 18.7도를
남기면서 가까운 바닥을 확보한다 — 대가가 가장 작은 지점이다.

### 되돌렸던 것을 다시 켰다 — `seen_min_dirs`

관측 방향 기록을 처음엔 '효과 없음' 으로 껐다. **그때는 검출이 병목이었다.**
포탑이 수평이라 누운 조난자를 52% 밖에 못 찾았고, 탐사를 아무리 잘해도 그
벽에 막혀 차이가 안 났다.

포탑을 고친 뒤 다시 쟀다(메인 15런). 지표는 '7/7 까지 걸린 시간' 이다 —
발견 인원은 이미 만점이라 구분력이 없다.

| 조건 | 7/7 | 걸린 시간(초) |
|---|---|---|
| base | 2/4 | 1780, 954 |
| **dirs** | **4/4** | **874, 1046, 762, 1105** |
| room | 2/3 | 1267, 1036 |
| both | 3/4 | 1115, 829, 1098 |

`room_bonus` 를 같이 켠 both 가 dirs 단독보다 낮다. 방 우선 보너스는
보태는 것이 없어 끈 채로 둔다.

**한 번 재고 되돌린 것이 영영 틀린 것은 아니다.** 병목이 바뀌면 값도
바뀐다. 그래서 되돌릴 때 기능과 스위치를 남겨 두는 것이 중요했다.

### 최종 검증 (2머신 16런, 제한 1800초)

두 값을 따로 쟀으므로(포탑=오로라, dirs=메인) 조합으로 다시 확인했다.
겸사겸사 머신 교차 확인도 된다.

| | |
|---|---|
| **7/7 완주율** | **13/16 (81%)** — 메인 7/8 · 오로라 6/8 |
| 7/7 까지 걸린 시간 | 중앙값 20분 (960~1790초) |
| 조난자별 발견률 | 누움 14/16 · 서있음 14~15/16 |
| 유령 검출 | 0건 / 16런 |

**누운 사람과 서있는 사람의 격차가 사라졌다.** 시작할 때는 52% 대 100%
였다.

| 설정 | 7/7 완주율 |
|---|---|
| 포탑 수평 · dirs 끔 | 22% |
| 포탑 0.20 | 67% |
| **포탑 0.10 + dirs** | **81%** |

주의: 완주율은 제한 시간에 따라 달라진다. 1790초짜리 런이 하나 있었는데
제한이 1800초라 10초 차이로 완주로 잡혔다. 시간을 더 주면 올라가고 짧게
주면 떨어진다.

### 1대에도 그대로 듣는다

채택한 두 값은 1대·2대 공유 코드에 있다. 1대로도 확인했다(2머신 7런,
무효 1런 제외).

| | 1대 | 2대 |
|---|---|---|
| 7/7 완주까지 | 중앙값 **26분** (22~38분) | 중앙값 **20분** (16~30분) |
| 7/7 완주율 | 7/7 (100%, 제한 60분) | 13/16 (81%, 제한 30분) |
| 조난자별 | 7명 전원 7/7 | 누움 14/16 · 서있음 14~15/16 |

README 에 적힌 1대 성적이 **57분**이었는데 **26분**이 됐다. 이 PR 을 머지하면
1대 구성도 같이 빨라진다 — 2대 기능만 얹는 것이 아니다.

2대가 1대보다 약 1.3배 빠르다(앞서 잰 1.4배와 비슷). 완주율은 제한 시간이
달라 직접 비교할 수 없다 — 공정한 비교는 걸린 시간이다.

### 같이 찾은 커버리지 버그

`_update_seen` 이 **0.3m 부터** 커버리지를 칠하고 있었다. 카메라가 못 보는
거리다. 로봇이 지나가면 주변 띠가 '봤음' 으로 칠해지는데 실제로는 그 바닥을
한 번도 안 본 것이고, 거기 누운 사람이 있으면 **영원히 못 찾는다**.

`cam_see_min` 으로 뺐다. 2.0m 와 비교했지만(2머신 18런) 차이가 없어
기본값 0.3 을 유지한다. 다만 **'효과 없음' 이 아니라 '천장 효과로 측정
불가'** 다 — 포탑을 고친 뒤로 누운 조난자를 이미 거의 다 찾아서 더 올릴
여지가 없었다. 버그 자체는 실재하므로 검출이 천장에 닿지 않은 조건(더
어두운 월드, 더 작은 대상, 더 빠른 주행)에서는 다시 볼 값어치가 있다.

## 3. 조난자 배치 변경

7명 중 4명이 멀쩡히 서 있었다. 재난 현장에 맞지 않고, 어려운 자세가 거의
시험되지 않았다. **누움 3 / 서있음 3(잔해에 가린 1 포함) / 휠체어 1** 로
바꿨다.

병원 이동침대(TrolleyBedPatient)는 뺐다. 재난 현장에 놓여 있는 것이
부자연스럽고, 발견률 41% 의 실패가 고칠 수 있는 종류가 아니었다 — 못 찾은
29런 중 19런에서 YOLO 가 사람 박스를 아예 못 만들었다. 침대 프레임이 몸을
가리고 로봇 카메라(0.5m)가 60cm 침대의 옆면만 본다.

생성기(`gen_rescue_large.py`)를 고치고 SDF 를 다시 생성했다.

## 4. 측정 도구

`tools/` 에 진단 도구, `tools/bench/` 에 실험 실행·집계를 넣었다. 전부
실제로 데이터를 망친 것을 잡으려고 만든 것이다.

| 도구 | 무엇을 잡나 |
|---|---|
| `kill_sim.sh` | 런처만 죽이면 남는 고아 노드. 쌓이면 CPU 가 모자라 카메라가 끊기고 검출이 조용히 0 이 된다 |
| `cam_hz.sh` | 위 고장의 직접 신호. Xid 도 없고 nvidia-smi 도 정상이라 다른 검사는 다 통과한다 |
| `gate_reject.sh` | 검출 파이프라인 생존. 키포인트 기각 0 이면 런 무효 |
| `which_missed.py` | 조난자별 발견률 — 어느 자리가 문제인지 |
| `reach_check.py` | 못 찾은 런에서 거기까지 갔는지 (커버리지 문제 vs 인식 문제) |
| `inspect_near.py` | 후보로 잡기는 했는지 (관문 문제 vs YOLO 가 못 봄) |
| `det_dist.py` | 자세별 검출 거리 분포 |
| `full_find.sh` | 7/7 달성 여부와 시각 |

### 실험 설계에서 지킨 것

여러 번 잘못된 결론을 내고 정착한 규칙들이다. `tools/bench/README.md` 에
적었다.

- **조건을 번갈아 돌린다** — 몰아서 돌리면 중간에 머신이 죽었을 때 뒤쪽
  조건만 표본이 통째로 사라진다
- **라운드마다 순서를 돌린다** — 고정이면 아침에 끊길 때 늘 마지막 조건만
  표본이 적다
- **조건은 파라미터로만 가른다** — 조건마다 다시 빌드하면 빌드 차이가 섞인다
- **런 전에 노드까지 죽인다** — 고아가 쌓이면 조용히 데이터가 망가진다
- **표본이 차기 전에 판정하지 않는다** — 3~7개에서 보이던 방향이 두 배
  쌓으면 사라지는 일을 여러 번 겪었다
- **머신을 두 대 이상에서 확인한다** — 한 머신에서만 좋은 것은 두 번 다
  노이즈였다

## 되돌린 것

기능과 스위치는 남기고 기본값만 껐다. 나중에 필요하면 파라미터로 켤 수 있고,
"이거 왜 안 켰지?" 에 대한 답이 커밋에 남아 있다.

| 항목 | 실측 | 기본값 |
|---|---|---|
| `seen_min_dirs` (방향 기록) | 처음엔 base 5.14 vs 5.86 로 구분 안 됨 | **2 (다시 켬)** |
| `ghost_need` (유령 자리) | base 5.14 vs 5.38, 머신별 순위 뒤집힘 | 0 (끔) |
| `room_bonus` (방 우선) | 0/3/6/12 에서 단조성 없음 | 0 (끔) |
| 누운 사람 관문 완화 | 54% vs 63%, p 약 0.55 | 6 / 0.50 (끔) |

`seen_min_dirs` 는 나중에 다시 켰다(위 참조). 검출이 병목일 때 잰 것이라
값이 묻혀 있었다.
