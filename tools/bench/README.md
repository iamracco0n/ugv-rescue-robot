# 벤치 스크립트

시뮬을 반복해 돌리고 결과를 집계하는 것들. `tools/` 의 진단 도구가 "한 런이
멀쩡한가" 를 보는 것이라면, 여기 있는 것은 "여러 런을 어떻게 설계해서
비교하는가" 를 담는다.

## 설계에서 지킨 것

여러 번 잘못된 결론을 내고 나서 정착한 규칙들이다.

**조건을 번갈아 돌린다.** 한 조건을 몰아서 돌리면 중간에 머신이 죽었을 때
뒤쪽 조건만 표본이 통째로 사라진다. 실제로 오로라가 GPU 문제로 6시간 만에
죽어 라운드 절반을 날린 적이 있다.

**라운드마다 순서를 한 칸씩 돌린다**(`OFFSET`). 고정 순서면 아침에 끊길 때
늘 마지막 조건만 표본이 적고, 머신이 밤새 더워지는 효과도 특정 조건에
몰린다.

**조건은 파라미터로만 가른다.** 조건마다 다시 빌드하면 빌드 차이가 결과에
섞인다. 환경변수로 넘겨 두 조건이 같은 바이너리를 쓰게 한다.

**런 시작 전에 앞 런을 통째로 죽인다**(`tools/kill_sim.sh`). `ros2 launch`
만 죽이면 노드가 고아로 남고, 쌓이면 CPU 가 모자라 카메라가 끊긴다. 그러면
검출이 0 이 되는데 Xid 도 없고 `nvidia-smi` 도 정상이라 조용히 데이터만
망가진다.

**표본이 차기 전에 판정하지 않는다.** 표본 3~7개에서 보이던 방향이 두 배
쌓으면 사라지는 일을 여러 번 겪었다. 중간에는 숫자만 본다.

## 실행

| 스크립트 | 무엇을 재나 |
|---|---|
| `ablation_gpu.sh` | 개선 항목을 하나씩 켜 가며(base/dirs/ghost/all) |
| `roombonus_sweep.sh` | 방 우선 보너스 크기 0/3/6/12 |
| `roomleave_run.sh` | 방을 덜 보고 나가는 횟수·재진입 |
| `lying_run.sh` | 작은 맵 누운 조난자 기준선 |
| `lying_ab.sh` | 누운 사람 관문 켬/끔 (작은 맵) |
| `lying_focus.sh` | 같은 방에서 시작해 동선 운 제거 |
| `complete_run.sh` | 시간을 넉넉히 줬을 때 7/7 까지 가는지 |

`chain_abl.sh` 는 앞 작업이 끝나면 다음 것을 잇는다. 기다릴 대상을 프로세스
이름이 아니라 **PID** 로 받는다 — 이름 패턴은 자기 자신을 잡거나 반대로
못 잡아서 시뮬 두 벌이 겹쳐 도는 사고가 난다.

## 집계

| 스크립트 | 지표 |
|---|---|
| `rb_tally.sh` / `rb_tally_one.sh` | 보너스별 재진입·이탈·발견 (전체 / 머신별) |
| `rb_full.sh` | 보너스별 7/7 달성률 |
| `focus_check.py` | 검출까지 걸린 시간(연속값) |
| `rtf_check.sh` | 시뮬이 실제로 몇 초 진행됐나(RTF) |

`rtf_check.sh` 는 머신 간 비교 전에 본다. 벽시계로 같은 시간을 돌려도 시뮬이
느리면 로봇에게 준 시간이 다른 것이라 비교가 성립하지 않는다.
